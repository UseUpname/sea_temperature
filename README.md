코드를 고치기 전에 아래 네 문서를 먼저 확인해 주세요. 사람과 AI(Claude Code, Copilot, Codex) 모두 같은 규칙을 따릅니다.

| 문서 | 무엇인가요 | 언제 보나요 |
|---|---|---|
| `AGENTS.md` | 팀 작업 규칙 (담당자·보안·Git·코드 품질) | 코드를 고치기 전에 항상 |
| `CLAUDE.md` | Claude Code가 `AGENTS.md`를 읽게 하는 연결 파일 | 직접 볼 일 없음 |
| `DESIGN.md` | 화면 디자인 공통 규칙 (초안) | 화면을 만들거나 디자인을 검토할 때 |
| `LAN_SETUP.md` | 팀 공용 DB(내부망)에 접속하는 방법 | DB에 처음 연결할 때 |

### 1. `AGENTS.md`: 팀 작업 규칙

**① 담당자 규칙 (가장 중요)**
- 다른 팀원의 파일은 **읽기만** 합니다. 고치려면 사용자의 명시적 승인이 필요합니다.
- 파일을 고치기 전에 `docs/OWNERSHIP.md`에서 담당자를 확인합니다. 표에 없으면 `git log`로 작성자를 확인합니다.
- 담당자가 다르거나 모르면 수정·삭제·이름 변경·이동을 하지 않습니다. 바꿀 내용, 이유, 담당자 이름을 보여 주고 승인을 기다립니다.
- 안 쓰는 것처럼 보여도 팀원의 코드·테스트·문서를 지우거나 "정리"하지 않고, 대신 알려 줍니다.
- `reset --hard`, 강제 푸시처럼 다른 사람의 작업을 날리는 git 명령은 쓰지 않습니다.
- 공용 코드를 고치기보다 새 파일이나 내 구역에 추가합니다.

**② 말투와 언어**
- AI는 한국어로, 결과부터 답합니다.
- README·문서·화면 문구·커밋 메시지는 한국어로 씁니다. 코드 주석은 화면 파일은 한국어, 파이썬은 영어로 씁니다. 변수·함수 이름은 영어입니다.

**③ 코드 품질**
- 요청한 것만 합니다. 요청하지 않은 기능·리팩터링·파일·문서는 만들지 않습니다.
- 기존 코드를 먼저 읽고 같은 방식을 따릅니다. 표준 라이브러리로 되는 일에 새 패키지를 넣지 않습니다.
- 쓰지 않는 코드, 주석 처리된 코드, 빈 TODO를 남기지 않습니다.
- 오류를 덮어 버리거나 가짜 대체값을 만들지 않습니다.
- 없는 API·테이블·패키지 이름을 지어내지 않습니다.
- 테스트를 돌려 보지 않고 "완료"라고 하지 않습니다. 못 돌렸다면 그렇다고 말합니다.

**④ 보안**
- 비밀번호·키·개인정보(이름, 생년월일, 전화번호)를 코드에 적거나 로그에 남기지 않습니다.
- `.env` 파일은 읽거나 커밋하지 않습니다. DB 계정은 각자 `backend/backend/.env`에만 둡니다.
- 브라우저는 DB에 직접 접속하지 않고 FastAPI 백엔드를 거칩니다.
- 공용 DB에 `DROP`·`DELETE`·`ALTER` 같은 위험한 명령은 승인 없이 쓰지 않습니다. 스키마 변경은 DB 서버 관리자가 합니다.

**⑤ Git**
- 요청받았을 때만 커밋합니다. 푸시나 기록 변경은 승인을 받습니다.
- 내 fork(또는 팀 저장소의 내 브랜치)에서 화면·기능별로 작업하고 팀 저장소로 PR을 보냅니다.
- `main`은 보호되어 있어 직접 push할 수 없습니다. PR로만 반영됩니다. 자세한 순서는 아래 [Git 작업 순서](#git-작업-순서)를 보세요.
- 커밋 전에 비밀정보가 없는지, 내 파일만 올라가는지 확인합니다.

**⑥ 실행·테스트**
- 백엔드: `backend/` 폴더에서 `..\.venv\Scripts\python.exe -m uvicorn backend.main:app --port 8000`
- 테스트: `py backend/run_tests.py` (DB 없이), `py backend/run_tests.py --db` (임시 스키마), `node --test "tests/**/*.cjs"` (화면 동작)

세부 규칙은 `.github/instructions/` 폴더에 주제별로 있습니다.

### 3. `DESIGN.md`: 디자인 공통 규칙 (초안)

- **아직 초안입니다.** `UNDECIDED`(미정)로 표시된 값(색, 글꼴, 간격 등)은 승인되지 않았습니다. 임의로 정하지 말고 후보를 제안해 승인을 받습니다.
- **우선순위:** 사용자 목표 달성 → 쓰기 쉬움·접근성 → 정보 구조·흐름 → 상태 설계 → 완성도 → 장식 순입니다. 위의 것을 아래 것 때문에 희생하지 않습니다.
- **화면 원칙**
  - 화면마다 주요 버튼은 하나만 둡니다.
  - 모든 것을 카드로 감싸지 않습니다.
  - 색만으로 의미를 구분하지 않습니다.
  - 글자 대비는 4.5:1 이상으로 합니다.
  - 브라우저를 200%로 확대해도 깨지지 않아야 합니다.
- **상태:** 데이터를 보여 주는 화면은 불러오는 중, 비어 있음, 오류, 성공 상태를 모두 만듭니다.
- **접근성:** WCAG 2.2 AA 기준이고, 폭 320px에서도 가로 스크롤이 없어야 합니다.
- **장식 기준:** 그라데이션, 유리 효과, 과한 그림자 같은 장식은 이유를 다섯 가지 질문으로 설명할 수 있을 때만 씁니다.
- **저작권:** 아이콘·이미지·글꼴은 쓰기 전에 `docs/design/ASSET_LICENSES.md`에 라이선스를 기록합니다. 참고한 디자인은 베끼지 않고 `docs/design/REFERENCE_LOG.md`에 기록합니다.
- **승인된 값 (2026-10-28):** 글꼴은 Noto Sans KR, 강조색은 `#007F98`(연한 색 `#E0F2F5`), 사이드바는 `#017896`, 모서리는 카드·버튼 6px·배지 3px입니다. 화면에는 `figma-theme.css`로 적용되어 있고, 전체 목록은 `DESIGN.md`의 승인 기록에 있습니다.

### 4. `LAN_SETUP.md`: 팀 공용 DB 접속

- 같은 공유기(내부망)에 있는 팀원은 서버 PC 한 대의 DB에 접속합니다. 각자 PostgreSQL을 설치할 필요가 없습니다.
- 접속 정보: 호스트 `192.168.0.96`, 포트 `5432`, DB `nifs_ocean`, 사용자는 본인 팀원 계정(`nifs_team1`·`nifs_team2`)입니다.
- 기본 권한은 **조회만** 가능합니다. 데이터 쓰기 권한은 계정을 만들 때 따로 받아야 합니다.
- 팀원 PC에서 FastAPI를 돌리려면 `team.env.example`을 `.env`로 복사하고 본인 계정과 비밀번호를 적습니다.
- 접속 확인: `Test-NetConnection 192.168.0.96 -Port 5432`의 결과가 `TcpTestSucceeded=True`면 됩니다.
- 서버 PC가 켜져 있어야 하고, 팀원은 `init-db`나 백업 복원을 실행하지 않습니다.

## 고수온 선제 상담 대시보드

양식 어가의 고수온 피해를 미리 막기 위해, 상담 담당자가 연락할 어가와 수온 예측을 한 화면에서 보는 대시보드입니다.

**배포 주소:** https://sea-temperature.onrender.com (접속하면 상담 홈으로 이동)

배포는 **Render 하나로** 합니다. FastAPI 백엔드가 API와 화면 4개를 같이 내보냅니다. 예전 Streamlit 버전은 쓰지 않아 삭제했습니다. `main`에 PR이 merge되면 Render가 자동으로 다시 배포합니다. 보통 1~2분 걸립니다.

Render가 쓰는 파일은 `backend/backend/` 폴더, 화면 HTML 4개, 공용 파일(`shell.js`·`shell.css`·`figma-theme.css`·`suhyup-logo.png`), `out/` 폴더입니다. 이 파일들의 이름이나 위치를 바꾸면 배포 사이트가 깨집니다. 공용 파일이 없으면 상단 바와 사이드바가 그려지지 않습니다. 새 화면은 `backend/backend/main.py`의 `SCREENS`에, 새 공용 파일은 `SHARED`에 넣어야 합니다.

### 화면

| 파일 | 화면 | 내용 |
|---|---|---|
| `consult_home.html` | 상담 홈 | 오늘 연락할 어가, 지역 수온, 신청·주의 추이 |
| `farm_detail.html` | 어가 상세 | 어가별 정보, 상담 기록, 어가 지역의 수온 추이 |
| `sea_forecast.html` | 수온 예측 | 지역별 21일 수온 예측 (1~7일 ROMS, 8~21일 ECMWF 보정), 어종별 위험 |
| `consult_status.html` | 고객 상담 현황 | 고객 목록과 과거 상담 내역 |

상단 바, 왼쪽 메뉴, 알림 패널은 따로 된 화면이 아니라 `shell.js`가 화면 4개에 공통으로 그립니다.

화면 4개는 모두 FastAPI 백엔드(`backend/backend/main.py`)가 같이 내보냅니다. 화면이 데이터를 받지 못하면 가상 데이터(SAMPLE)를 쓰고 화면 위에 경고를 띄웁니다.

> ⚠️ 각 화면의 `const API_BASE = …` 줄은 로컬과 배포 주소 모두에서 동작하도록 맞춰 둔 줄입니다. 고치지 마세요. 예전 파일로 작업하다 이 줄이 되돌아가면 배포 사이트가 서버에 연결되지 않습니다.

### 백엔드 실행

1. `backend/backend/team.env.example`을 같은 폴더에 `.env`로 복사하고 `DB_USER`·`DB_PASSWORD`에 **본인 팀 계정**을 적습니다. `.env`는 깃허브에 올라가지 않습니다. 비밀번호를 단톡·캡처에 노출하지 마세요.
2. 해당 계정에 `insurance` 스키마 조회 권한이 있어야 합니다(없으면 503). 권한은 스키마 소유자(nifs_team2)나 서버 관리자가 부여합니다.
3. 프로젝트 최상위 폴더에서:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\backend\requirements.txt
cd backend
..\.venv\Scripts\python.exe -m uvicorn backend.main:app --port 8000
```

4. `http://127.0.0.1:8000/docs`에서 API를 직접 눌러 볼 수 있습니다. localhost·127.0.0.1 주소는 CORS 허용되어 있고, 다른 주소는 `.env`의 `CORS_ORIGINS`에 추가합니다.

### 화면 확인 (로컬)

백엔드를 켠 상태에서 아래 둘 중 하나로 엽니다.

- **백엔드 주소로 열기 (배포와 같은 방식):** `http://127.0.0.1:8000/` → 상담 홈으로 이동합니다.
- **화면만 따로 띄우기 (HTML 수정 중일 때):** 저장소 최상위 폴더에서 `py -m http.server 8765`를 켜고 `http://localhost:8765/consult_home.html`로 엽니다. 데이터는 8000번 백엔드에서 받아옵니다.

HTML 파일을 더블클릭해서 열면(`file://`) 서버에 연결할 수 없어 가상 데이터만 보입니다.

확인할 것: 상단에 **"DB 연결됨"**이 보이고 가상 데이터 경고가 없으면 정상입니다.

## Git 작업 순서

`main`에는 보호 규칙이 걸려 있습니다. 직접 push, 강제 push, 삭제가 막혀 있고 **PR로만** 반영됩니다.

**fork로 작업하는 팀원**
1. 작업 시작 전에 내 fork 페이지에서 **Sync fork**를 눌러 최신 `main`을 받습니다. 예전 파일 위에 작업하면 다른 사람의 수정이 되돌아갈 수 있습니다.
2. 내 컴퓨터에서 `git pull` 후 작업하고 커밋합니다.
3. 내 fork에 push하고 GitHub에서 팀 저장소 `main`으로 PR을 엽니다.

**팀 저장소에 쓰기 권한이 있는 팀원 (Collaborator)**
1. 최신 `main`을 받습니다: `git pull origin main`
2. 내 브랜치에서 작업합니다: `git switch -c 브랜치이름`
3. 처음 push할 때 브랜치를 연결합니다: `git push -u origin 브랜치이름`. 이후에는 `git push`만 하면 됩니다.
4. GitHub에서 `브랜치이름 → main`으로 PR을 엽니다.

PR은 저장소 관리자(sooui9)가 확인하고 merge합니다. merge된 브랜치는 삭제합니다.
